# Roadmap

`TASKS.md` is the status authority. This page records only the durable product
direction and major remaining seams.

## Shipped foundation

- Pose-authoritative Schema 2 editing with optional GLB placement surfaces.
- Mechanics-free simulation, mapping, wiring, persistence, and project ZIPs.
- Deterministic automatic gap detection for unambiguous flat simple N-gons.
- Closed-boundary validation and exact STL compilation with pinned Manifold.
- Browser-first assembly-package generation and exact asset reopen.
- Authored output routes, GPIOs, installed quarter turns, ledmap generation,
  printable wiring manuals, and assumed WLED deployment identity.
- Checked-in pinned WLED WASM with exact integrity verification; rebuild source
  and tools stay on `generate/wled-simulator`.
- Real Chromium authoring, generation, route, manual, and portability journeys.

## Current product milestone

Make the manual 41-panel sculpture reproduce the simulator's static address and
RGB output on the selected ESP32/WLED target:

```text
shared guarded export policy
  -> pinned firmware build
  -> deterministic diagnostic frames
  -> measured panel and as-built route evidence
  -> all-address parity proof
```

Mapping assumptions do not replace electrical approval. Full operation remains
blocked by `PWR-010`.

## Known technical seams

- Derive LED dimensions from the selected panel profile throughout validation,
  export, reload, and display.
- Bound ZIP entry count, size, total expansion, and compression ratio.
- Preflight panel footprints during automatic placement.
- Strengthen ledmap fingerprints beyond the low 16 bits of each index.
- Add correction tools only when a real ambiguous gap arrangement provides a
  concrete fixture.
- Split `web/src/main.ts` only along covered behavior boundaries.
- Keep Schema 2 as the only authored sculpture and mapping input. Historical
  Schema 1 files remain available through Git history only.

## Product constraints

- Do not add a second pose, mapping, route, boundary, or project-file authority.
- Add fabrication capability one evidence-backed shape or requirement at a
  time.
- Do not claim firmware, transport, network, audio, or electrical behavior
  before each claim has implementation and physical evidence.
- Stop a slice when its acceptance criteria and relevant checks pass. Record
  later improvements as separate tasks.
